# 项目级快照分析方案设计 (Project Snapshot Analysis Design)

> 版本: 3.2 (落地执行细则版)
> 类型: 通用方案 (行业无关)
> 核心理念: 配置驱动的上下文重构 + AI 战略决策 (Config-Driven Context Reassembly + AI Strategic Decision)

## 1. 设计背景与哲学

传统的“多任务分析”往往是简单的“数据累加”，缺乏深度。本方案通过**“重构”**（Re-construction）还原真实市场格局，并引入 **LLM (大语言模型)** 作为**“AI 战略顾问”**，直接输出可执行的商业建议，而非堆砌图表。

**核心价值主张**：
1.  **宏观战略 vs 微观战术**：与任务级 Insights 形成完美互补。任务级负责具体的语境归因（战术），项目级负责全域的格局判断（战略）。
2.  **重结果，轻形式**：移除华而不实的复杂图表（如网络图），聚焦于直接辅助决策的量化指标和文字建议。
3.  **智能对齐 (Smart Alignment)**：利用 LLM/Embedding 解决复杂实体/观点的归一化，确保数据底座扎实。
4.  **业务导向**：直接回答“谁赢了”、“赢在哪里”、“市场在关注什么”。

## 2. 分析输入模型 (Input Model)

分析引擎不预设行业知识，完全依赖用户在生成报告前的**“上下文配置”**。

### 2.1 角色定义 (Role Definition) - "我是谁"
*   **分析主体 (Subject)**: 单选。用户关心的核心品牌/对象。（例如：`XPEL`）
*   **核心竞品 (Key Rivals)**: 多选。作为参照系的竞争对手。（例如：`3M`, `威固`）

### 2.2 数据源分组 (Source Grouping) - "战场在哪"
将参与分析的任务（Tasks）映射为三种**语境 (Context)**：

| 分组代码 | 分组名称 | 定义 | 商业属性 |
| :--- | :--- | :--- | :--- |
| **Group A** | **主场任务** | 搜“分析主体”的任务 | **私域/存量**。反映核心粉丝/已购用户的反馈。 |
| **Group B** | **客场任务** | 搜“核心竞品”的任务 | **防御/进攻区**。反映竞品用户的看法及我方的渗透力。 |
| **Group C** | **广场任务** | 搜品类词/泛词的任务 | **公域/增量**。反映真实的市场认知 (Top of Mind) 和行业痛点。 |

## 4. 落地执行细则 (Execution Guide)

本章节详细描述各环节的业务执行逻辑与边界处理，供产品经理与开发人员参考。

### 4.1 用户配置环节 (Configuration Phase)
**目标**：以最小的用户操作成本，获取最准确的上下文定义。

1.  **自动推断逻辑 (Auto-Inference)**：
    *   当用户进入配置页时，系统应尝试**预填充**：
        *   **Subject**: 扫描所有选中任务的高频实体 Top 1。
        *   **Task Grouping**:
            *   若 `TaskName` 包含 Subject -> 预选为 **Group A (主场)**。
            *   若 `TaskName` 包含 Rivals -> 预选为 **Group B (客场)**。
            *   若 `TaskName` 均不包含 -> 预选为 **Group C (广场)**。
    *   *原则*：默认全自动，用户只需 Check & Confirm。

2.  **完整性校验 (Validation)**：
    *   **必须项**：必须选定 Subject，且至少有一个任务被归类。
    *   **缺失警告**：
        *   若 **Group C (广场)** 为空 -> 提示“缺少行业通用数据，将无法计算‘心智占有率’和‘行业痛点’，建议补充‘品类词搜索任务’”。
        *   若 **Group B (客场)** 为空 -> 提示“缺少竞品数据，将无法评估‘进攻渗透率’”。
    *   *原则*：允许数据缺失，但需明确告知后果（分析模块降级）。

### 4.2 智能清洗与对齐环节 (Smart ETL Phase)
**目标**：在不消耗巨额 Token 的前提下，实现高精度的跨任务数据合并。

1.  **实体合并优先序 (Entity Merge Priority)**：
    *   **P0 (Parent 强一致)**：若两个实体 `tags.parent` 相同（且非空），直接合并。
        *   *例*：Task A "XPEL LUX" (Parent: XPEL) + Task B "LUX PLUS" (Parent: XPEL) -> 合并。
    *   **P1 (规则强匹配)**：若名称完全一致或互为子串（长度差<2），直接合并。
    *   **P2 (Embedding 弱匹配)**：
        *   *触发条件*：仅针对**高频孤立实体**（热度 Top 50 且未被 P0/P1 合并）。
        *   *逻辑*：计算向量相似度 > 0.92。
        *   *兜底*：若相似度在 [0.85, 0.92] 之间，标记为“疑似同义”，在前端展示时可折叠，但不自动合并计算。

2.  **属性标准化逻辑 (Attribute Norm)**：
    *   **去噪**：过滤掉仅出现 1 次的长尾属性（避免雷达图维度过多）。
    *   **LLM 聚类触发**：仅当 Top 属性中存在语义重复（如“价格高”和“太贵了”同时在 Top 10）时触发。
    *   *原则*：统计优先，AI 辅助。

### 4.3 分析模块生成环节 (Generation Phase)
**目标**：根据数据丰富度，动态调整报表呈现。

1.  **模块降级策略 (Graceful Degradation)**：
    *   若 **Group C 缺失** -> **隐藏** “心智占有率” 和 “行业痛点雷达” 模块。
    *   若 **Group B 缺失** -> **隐藏** “渗透率” 指标，SWOT 矩阵退化为“单品牌分析”。
    *   若 **平台单一** -> **隐藏** “平台剪刀差” 模块。

2.  **AI 顾问提示词策略 (Prompt Strategy)**：
    *   **输入数据**：不仅传入 JSON，还需传入 **Data Quality Flag**（如：“注意：本次分析缺少竞品数据”）。
    *   **输出控制**：强制要求 LLM 输出 **“三段式”** 建议（营销/产品/公关），并要求每条建议必须引用具体数据（如“根据 3M 在 Group A 的渗透率为 20%...”）。禁止输出“建议加强管理”这种正确的废话。

## 5. 核心分析模块 (Analysis Pillars)

### 模块一：全域格局分析 (Market Landscape)
*回答：市场地位与真实资产*

1.  **自然心智占有率 (Organic Mind Share)**：仅基于 **Group C (广场任务)**。利用 `parent` 字段，将子产品回溯到品牌进行统计。**这是衡量品牌真实统治力的核心指标**。
2.  **全域声量份额 (Total SoV)**：所有任务的加权热度。
3.  **渗透率分析**：Subject 在 Group B (客场) 的出现频率，代表“截流”能力。

### 模块二：产品力攻守矩阵 (Product SWOT Matrix)
*回答：长板与致命伤*

*   **维度**：自动发现 Top N 关注点。
*   **矩阵**：X轴(提及率) * Y轴(情感净值)。
*   **输出**：明确 Subject 的 **绝对优势区** (护城河) 和 **急需改进区** (阿喀琉斯之踵)。

### 模块三：平台阵地透视 (Platform Strategy)
*回答：平台策略是否撕裂*

*   **平台剪刀差**：对比不同平台（如 抖音 vs 小红书）的热度/情感排名。
*   **价值**：识别“跛脚型”（热度偏科）或“崩塌型”（口碑偏科）风险。

### 模块四：行业舆论雷达 (Opinion Focus)
*回答：行业风向与机会*

*   **行业共性痛点**：基于 Group C 的观点数据。发现行业普遍解决不好的问题（如“留胶”）。
*   **品牌错位 (Gap)**：对比“行业关注点”与“品牌被提及点”。
    *   **怀才不遇**：行业关注某点，但我没宣传。
    *   **无妄之灾**：行业不关注某点，但我被骂得很惨。

## 6. AI 战略顾问 (AI Strategic Advisor)

这是本方案的**大脑**。不画花哨的图，而是输出**“人话”建议**。

### 6.1 输入上下文 (Context)
将计算好的结构化 JSON (SoV, SWOT矩阵, 剪刀差数据, Top痛点) 喂给 LLM。

### 6.2 结构化输出 (Structured Output)
要求 LLM 扮演“高级商业分析师”，输出以下三部分深度建议：

1.  **投放/营销建议 (Marketing Strategy)**
    *   *示例*：“监测到‘隐形车衣’品类词下品牌存在感仅为 5%（远低于竞品 3M 的 20%），且行业正处于‘哑光’需求上升期。建议立即增加‘哑光车衣’相关的品类词内容投放，抢占增量市场。”
2.  **产品/服务改进建议 (Product Improvement)**
    *   *示例*：“‘售后难找’是您独有的高频负面（热度 Top 3，竞品无此问题）。这已成为转化的最大阻碍。建议立即优化官网/小程序的门店查询功能，并在物料中显著强调‘全国联保’。”
3.  **舆情/公关建议 (PR & Risk)**
    *   *示例*：“小红书平台出现口碑倒挂（热度高但情感分低），主要集中在‘价格’吐槽。建议在小红书侧重‘长期持有成本’的教育，通过‘贴膜省漆面修复费’的逻辑化解高价抗性。”

## 8. 方案互补性总结

本方案与现有的任务级 Insights 构成了完整的决策闭环：

| 特性 | **项目级快照分析** | **任务级 Insights 分析** |
| :--- | :--- | :--- |
| **定位** | **战略罗盘** (方向判断) | **战术显微镜** (细节归因) |
| **视角** | 全域重构 (Re-construction) | 局部切片 (Slicing) |
| **数据流** | 消费清洗后的聚合数据 | 生产基础数据 (实体/情感) |
| **关系** | **上层建筑** | **基础设施** |

两者 **互为表里，缺一不可**。
